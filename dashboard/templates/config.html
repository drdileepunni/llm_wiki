Monitoring protocols define when a clinical finding is intentionally permissive — expected, tolerable, or already managed. The problem tracker gates alerts against these: if a scenario applies, the alert is suppressed. Each protocol matches patients via applies_when substrings (editable in the JSON). Currently active: hypertension, GCS, respiratory, haemoglobin, lactate.
Note: category-matching keywords for domain rule injection (clinical_rule_blocks.py) are not stored in GCS — editing them requires a code change and redeploy.

Per-lab thresholds injected into the problem-tracker prompt. An alert fires only when the most recent value crosses the floor/ceiling or delta threshold.

Symptom rules require an objective criterion to be met before the model can alert on a subjective complaint (pain, nausea, etc.).

Per-lab maximum result age before the pipeline treats the value as too stale to alert on. A hard code gate enforces these limits — even if the model decides to alert, the alert is suppressed if the lab draw is older than the configured limit. The global default is 24h for all labs not listed here.
Format: { "lab_name": hours } — e.g. { "lactate": 12, "troponin": 6 }. Lab names must match what the pipeline's get_lab_trend() tool returns (lowercase).

Runtime settings loaded from GCS app_settings/ on every pipeline run. Click Edit next to any setting to modify it.
